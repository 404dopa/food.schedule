# Bayti Kitchen (بيتي كيتشن) 🍲

تطبيق متكامل واحترافي لإدارة المطبخ ومؤونة المنزل وجدول الوجبات الذكي، مستوحى من تجربة KitchenPal، ومبني بأحدث المعايير الهندسية لدعم العمل الكامل دون اتصال بالإنترنت (**Offline-First**)، مع مزامنة موثوقة ونظام معاملات ذرية مشدد لحركات المخزون والمشتريات.

---

## 1. المميزات الرئيسية (Core Features)

### 🧭 بنية التنقل وقواعد الواجهة (Navigation Rules)
- **4 واجهات رئيسية فقط** عبر شريط تنقل سفلي ثابت (`Bottom Navigation`):
  1. **الرئيسية (Home)**: لوحة التحكم اليومية بوجبات اليوم، التكاليف، وحالة توفر المقادير.
  2. **المطبخ (Kitchen)**: إدارة المكونات والمخزون، أسعار الوحدات، تنبيهات النقص، وتعديل الكميات.
  3. **التسوق (Shopping)**: قائمة التسوق الذكية المحسوبة آلياً، تسجيل المشتريات، وتتبع المصاريف.
  4. **الوصفات (Recipes)**: كتيب الطبخ المنزلي، حساب تكلفة الوجبات، وتحديد النواقص بدقة.
- **أقصى عمق تنقل = 2 (Maximum Navigation Depth = 2)**: منع النوافذ المتداخلة نهائياً.
- **نظام Bottom Sheet موحد**: لجميع عمليات الإضافة والتعديل والعرض، مع حواف علوية دائرية، زر إغلاق واضح، وسحب للأسفل للإغلاق.
- **تصميم يدعم العربية بالكامل (RTL)** مع تبديل سلس بين الوضع النهاري والليلي (Light / Dark Theme).

---

### 🛡️ قاعدة الخصم الذرية الحساسة (Critical Inventory Rule)
- **لا تُخصم أي مكونات** عند عرض الوجبة أو جدولتها أو تعديلها.
- يتم الخصم **فقط** عندما يضغط المستخدم على زر **"تم تحضير الوجبة" (Meal Prepared)**.
- **تنفيذ الخصم:**
  1. حساب المقادير المطلوبة بناءً على عدد الحصص.
  2. التحقق من كفاية جميع المكونات في المخزن.
  3. في حال وجود أي نقص لأي مادة، **تُلغى العملية بالكامل** دون أي خصم جزئي، وتُعرض المواد الناقصة للمستخدم.
  4. عند التوفر، يُنفذ الخصم داخل **Database Transaction واحدة** مع تسجيل حركة استهلاك (`consumption`) وتوثيق المعاملة باستخدام **مفتاح مانع للتكرار (Idempotency Key / UUID)**.

---

### ⚡ العمل دون اتصال والمزامنة (Offline First & Sync Engine)
- تخزين محلي متكامل عبر **IndexedDB** (`idb`) لقراءة وتعديل البيانات بالكامل دون إنترنت.
- **Offline Operations Queue**: تسجيل أي عملية إضافة/تعديل دون اتصال بـ UUID وتوقيت دقيق.
- مزامنة خلفية تلقائية عند عودة الاتصال مع حماية صارمة من تكرار المعاملات.

---

### 📊 استيراد وتصدير Excel حقيقي (.xlsx)
- تصدير فوري لبيانات المكونات والمخزون، والوصفات.
- استيراد ملفات Excel مع فحص الأعمدة، كشف التكرار، ومعاينة جدولية حية قبل الاعتماد.
- إنشاء المكونات والتصنيفات غير المسجلة تلقائياً أثناء الاستيراد.

---

### 📱 تطبيق Android APK أصيل (Capacitor)
- جاهز للبناء والتثبيت كـ Android APK أصيل.
- المعرف: `com.baytikitchen.app`
- الاسم: `Bayti Kitchen`
- مشاركة نفس كود React بين الويب والأندرويد مع دعم RTL وOffline.

## 2. بنية المشروع (Project Structure)

```
bayti-kitchen/
├── backend/                  # خادم Go REST API (Gin + GORM + SQLite/PostgreSQL)
│   ├── cmd/server/main.go   # نقطة الدخول الرئيسية
│   ├── internal/
│   │   ├── config/          # قراءة متغيرات البيئة
│   │   ├── handlers/        # معالجات HTTP والمسارات
│   │   ├── models/          # نماذج GORM وقواعد البيانات
│   │   ├── repository/      # مستودعات البيانات والـ Transactions
│   │   ├── seed/            # بيانات تجريبية للأكلات العراقية
│   │   └── services/        # منطق الأعمال (الوحدات، الخصم، التسوق، الإكسل)
│   └── tests/               # اختبارات الوحدة والتكامل
├── frontend/                 # واجهة React + TypeScript + Vite + Tailwind CSS
│   ├── src/
│   │   ├── components/      # الواجهات، الألسنة، وBottom Sheets
│   │   ├── context/         # سياق التطبيق والثيم والمزامنة
│   │   ├── services/        # عميل الـ API وقاعدة IndexedDB
│   │   └── types/           # تعريفات TypeScript
│   └── capacitor.config.ts  # إعدادات Capacitor لـ Android
├── android/                  # مشروع Android الأصلي المبني بـ Gradle
├── docker/                   # ملفات Dockerfile و Nginx
├── migrations/               # ملفات ترحيل قاعدة البيانات SQL
├── docs/                     # التوثيق الهندسي ومواصفات الـ API
├── scripts/                  # سكربتات النشر الاحتياطي والـ VPS
├── docker-compose.yml        # تشغيل بيئة الإنتاج المتكاملة
└── .env.example              # نموذج متغيرات البيئة
```

## 3. التشغيل المحلي السريع (Local Development)

### متطلبات التشغيل:
- Go 1.22+
- Node.js 18+

### تشغيل الـ Backend (Go + SQLite):
```bash
cd backend
go run ./cmd/server
```
*سيعمل الخادم تلقائياً على المنفذ `8080` وسيقوم بإنشاء قاعدة بيانات SQLite محلية وزرع الأكلات العراقية الأصيلة تلقائياً.*

### تشغيل الـ Frontend (React + Vite):
```bash
cd frontend
npm install
npm run dev
```
*افتح المتصفح على: `http://localhost:5173`.*

## 4. تشغيل الاختبارات (Running Tests)

مشروع Bayti Kitchen مغطى باختبارات تكامل فعلية تغطي كافة السيناريوهات الحساسة:
- إضافة مكون وتعديل المخزون.
- منع المخزون السالب.
- إضافة وصفة وحساب تكلفتها التقديرية بالدينار العراقي.
- جدول وجبات وإضافة أكثر من وجبة في اليوم.
- **معاملة تحضير الوجبة الذرية (Atomic Preparation Transaction):**
  - الخصم الناجح وتحديث الأرصدة.
  - منع الخصم المكرر بواسطة الـ Idempotency Key.
  - التراجع الكامل (Rollback) عند نقص أي مادة في المخزن.
- مزامنة العمليات دون اتصال (Offline Sync).
- تصدير واستيراد ملفات Excel حقيقية.

لتشغيل الاختبارات:
```bash
cd backend
go test -v ./tests
```

## 5. النشر على VPS باستخدام Docker Compose

التبديل بين PostgreSQL للإنتاج وSQLite للتطوير يتم بكل بساطة عبر متغير البيئة `DB_TYPE` دون أدنى تغيير في الكود!

### خطوات النشر:
```bash
# 1. نسخ ملف الإعدادات
cp .env.example .env

# 2. تشغيل الحاويات في الخلفية
docker compose up -d --build

# 3. التحقق من سلامة الخدمات
docker compose ps
curl http://localhost/health
```

## 6. بناء تطبيق Android APK

تم تجهيز مشروع الأندرويد الأصلي بواسطة Capacitor:
```bash
cd frontend
# بناء ملفات الواجهة
npm run build

# مزامنة الواجهة مع مجلد أندرويد
npx cap sync android

# فتح المشروع في Android Studio أو البناء عبر Gradle:
cd ../android
./gradlew assembleDebug
```
*يتم إنتاج ملف الـ APK في المسار:*
`android/app/build/outputs/apk/debug/app-debug.apk`
